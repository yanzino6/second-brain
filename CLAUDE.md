# CLAUDE.md — Second Brain Operating Rules
 
## Identity
- Read USER.md, SOUL.md, and IDENTITY.md at the start of every session.
	- Proactivity is the key, always analyze every single document and prompt  so u can update documents and information
 
## Structure
- New raw material goes to 00-Inbox until processed.
- One canonical note per person (10-People), project (20-Projects),
  and company (30-Companies). Never create duplicates — search first.
- Meeting notes live in 40-Meetings, named YYYY-MM-DD Title.
- Real folders on disk use `NN - Name` (e.g. `01 - People`, `05 - Knowledge`,
  `07 - Archive`) — the `N0-Name` names above are shorthand for the same folders.
 
## Knowledge classification
- Before filing any note in Knowledge (05 - Knowledge), ALWAYS verify whether
  it belongs to a specific client/project.
  - Client- or project-specific knowledge → per-client subfolder
    `05 - Knowledge/<Client>/` (e.g. `05 - Knowledge/Biancogres/`).
  - Only truly general, reusable, client-agnostic knowledge stays in the
    Knowledge root.
- Never mix knowledge from different clients in the same note or folder — each
  client is an isolated compartment (see IDENTITY.md).
 
## Linking
- Link only when the connection is meaningful and durable.
- Every meeting note must link to its attendees and project.
- Update the relevant MOC in 60-MOCs when adding major notes.
 
## Writing style
- Concise. Bullets over paragraphs. No filler.
- Frontmatter on every note: type, tags, and relevant links.
 
## Safety
- Never delete a note; move superseded material to 90-Archive.
- When consolidating duplicates, preserve all unique information.
- Ask before making changes that touch more than 20 files.
